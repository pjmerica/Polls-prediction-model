# `outputs/` — generated predictions (gitignored)

Everything here is **regenerated by every refresh run**. Nothing in this folder is a source of
truth, and nothing here except this README is committed. Delete the whole folder and one
`py -X utf8 src/refresh_dashboard.py --no-feeds` recreates it.

Created 2026-08-08; these nine files previously sat loose in the repo root.

| file | written by | what |
|---|---|---|
| `predictions_2026.csv` | `src/predict.py` | win probability per candidate (`win_prob`, `win_prob_norm`) |
| `margin_predictions_2026.csv` | `src/predict_margin.py` | predicted vote margin |
| `primary_predictions_2026.csv` | `src/predict_primary.py` | primary nominee probability |
| `primary_margin_predictions_2026.csv` | `src/predict_primary_margin.py` | primary vote margin |
| `model_explanations_2026.json` | `src/explain_2026.py` | SHAP top-10 per race, general models |
| `primary_explanations_2026.json` | `src/explain_primary.py` | SHAP top-10 per race, primary models |
| `*_meta.json` | each predictor | run stamp: `generated_at`, `polls_max_end_date`, row/race counts |

## Read the `*_meta.json` sidecars before trusting a CSV

They record when the file was generated and how fresh the underlying polls were. A prediction
CSV with no context is impossible to date — the sidecars exist because CI checkouts reset file
mtimes.

## Where the dashboard actually reads from

Not here. `refresh_dashboard.py` **copies** these into the sibling polling-agg repo as
`data/processed/model_*.csv`, and *that* repo commits its copy — which is what the published
site serves. So:

- Regenerating here changes nothing on the site until the copy is committed **in polling-agg**.
- polling-agg looks for `outputs/` first and falls back to the old repo-root location, so the
  two repos can sit at different commits during a rollout.

## Why these are not committed

They were, while they sat in the repo root — but only by accident: the root `*.csv` rule does
not cover `.json`, so the two large explanation JSONs (4.2MB + 0.5MB) got committed while the
CSVs beside them did not. That produced merge conflicts on files nothing reads from this side
whenever CI regenerated them. The whole folder is ignored now, deliberately.

## Writing to this folder

Use `paths.out("name.csv")` — never a hand-spelled path, and never
`os.path.join(dirname(__file__), ...)`. `paths.out()` also creates the directory on first use,
so a fresh clone (which has no `outputs/`) works without a setup step.

Import it as a module (`import paths as _paths`, then `_paths.out(...)`): `out` is a very
common local variable name in this codebase and a bare `from paths import out` gets shadowed.
