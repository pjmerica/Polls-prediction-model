# `data/` — every committed input + trained model artifact

58 files are committed here. **Nothing in the pipeline re-downloads on a normal run**: all
historical data was pulled once and committed, and is re-pulled only to *extend* it to a new
month or cycle. The one exception is the live generic-ballot fetch at predict time
(current-cycle info cannot be frozen by definition).

Per-column definitions live in [../docs/DATA_DICTIONARY.md](../docs/DATA_DICTIONARY.md);
every source URL and how it was found is in [../docs/DATA_SOURCES.md](../docs/DATA_SOURCES.md);
exact time windows are in [../docs/METHODOLOGY.md](../docs/METHODOLOGY.md).

## The gitignore inversion (read this before adding a file)

`.gitignore` ignores `data/*` and `*.csv` **wholesale**, then re-allows each committed file by
name. So a new file here is **invisible to git by default** — and therefore invisible to CI,
which checks out a fresh clone.

This has bitten the project repeatedly: `primary_results_2026.csv` was missing in CI, so the
nightly refresh regenerated predictions with defeated primary candidates still in them. If you
add a file the pipeline needs, **add an un-ignore line for it** and confirm with
`git check-ignore -v data/<file>`.

## What's in here, by role

### Election results (the labels)
`res_senate.csv`, `res_house.csv`, `res_governor.csv` — per-candidate results.
`races.csv` — race-level metadata incl. `incumbent_party` (there is **no incumbent name**
column anywhere; this is why `is_incumbent` is party-level). `senate_*`/`house_*`/
`governor_{current,historical}.csv` — seat rosters.

### Polls
`raw_polls_538.csv` (frozen 1998–2016 archive), `polls_2026_long.csv` (the live cycle),
`primary_polls_long.csv` + `primary_polls_wikipedia.csv` (primary side).
The 14MB joined training file, `polls_long_with_results.csv`, lives in the **repo root**, not
here — it is force-added past the `*.csv` rule so CI can see it.

### Context features
`macro_monthly.csv` (economy), `approval_monthly.csv`, `generic_ballot_monthly.csv` +
`generic_ballot_hist_538.csv`, `lean_states.csv` / `lean_districts.csv`,
`district_pvi_current.csv`, `redistricted_2026.csv`.

### Money
`fec_summary.csv`, `fec_detail.csv`, `governor_finance.csv`.

### Candidate bios / identity
`candidate_bios.csv` is **the** file every consumer reads — it is built by
`pipeline/build/build_office_level_table.py` from the per-office scrapes
(`candidate_bios_{senate,governor,house,ballotpedia}.csv`) plus hand-codes in
`candidate_bios_manual.csv`. Do **not** run `combine_candidate_bios.py`; it writes this same
path with a leak-prone frozen `office_level` and now refuses to run.
`name_aliases.csv` — hand-curated, exact-match only (an automated surname merge would
conflate different people). `candidate_party_overrides.csv` — `model_party` vs
`display_party`. `dropped_out_2026.csv` — withdrawn candidates to filter out.

### Primary results
`primary_results_2026.csv` (**authoritative once a primary is called** — this is what removes
defeated candidates from the general feed), `primary_results_hist.csv`,
`primary_results_deep_hist.csv`, `house_primary_results_hist.csv`, `primary_dates_*.csv`.

### Trained model artifacts (regenerated by a retrain, committed)
`model_xgb.json` + `model_features.json` (win), `margin_model_*` , `primary_model_*`,
`primary_margin_model_*`, and the two `fundamentals_model_*` sets.
**The `*_features.json` files are the feature CONTRACT** — predict-time asserts compare
against them, so a mismatch means the model and the code disagree.

### Frozen snapshots
`dataset_2026_meta.json` and `*_snapshot_2026-07-29.csv` are point-in-time records. Their
numbers are *deliberately* stale (e.g. `natl_env_used: 5.57` vs a later live 6.75) — do not
"correct" them.

## Cached keys go stale

17 CSVs here cache `cand_key` as a column (measured 2026-08-08:
`grep -l cand_key data/*.csv`). Any change to `features.norm_name` re-keys every join and
makes them wrong — re-run `tools/scripts_rekey_cand_key.py` (dry run first).
